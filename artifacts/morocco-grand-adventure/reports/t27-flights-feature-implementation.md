# T27 — Morocco Flights & Smart Travel Planner: Implementation Report

**Status:** First production-quality version implemented and validated; a pre-commit review then found two concrete issues, both fixed and re-validated (§7). Everything remains uncommitted in the working tree for review, exactly as instructed. No commit, push, or deploy was performed.

---

## 1. What this is

A new page at `/flights` (and automatically at `/{lang}/flights` for all 10 other locales, via the existing routing convention) that helps travelers:
- Explore a verified directory of 14 Moroccan airports.
- Search a route and get sent to a real airline/aggregator to complete the search — no fake fares, no fake availability.
- See honest, sourced facts about a handful of domestic Moroccan routes (including the ones that currently have **no** verified scheduled service).
- Plan a rough trip budget privately, client-side.
- Cross-link into Morocco Grand Adventure's existing tours and contact channels.

This is a **free flight-discovery and comparison guide**, not a booking agency. No payments, no tickets, no fabricated prices, and no account requirement anywhere on the page.

## 2. Repository audit (before writing code)

- **Stack:** Vite 7 + React + `wouter` routing, base path `/{lang}`, lazy-loaded route components (`src/App.tsx`).
- **SEO:** a single `route-metadata.ts` source of truth (English `routeMetadata` object + per-locale override objects), consumed by `LocalizedHead` at runtime and by `scripts/prerender.ts` at build time. Missing locale overrides fall back to English by design — an already-established, already-accepted pattern (confirmed by reading `getLocalizedRouteMeta`).
- **Prerendering:** `scripts/prerender.ts` hand-builds a separate, crawler-facing static HTML snapshot for every route (not a React SSR render) via an `add(path, outFile, contentFn, schemas)` registry. The sitemap (`scripts/generate-sitemap.mjs`) is generated by **walking the actual `dist/` output**, so a newly-registered route is picked up automatically — no separate sitemap list to maintain.
- **i18n:** `src/i18n/locales/{lang}.ts`, 11 locales. The `en.ts` file carries a "do not hand-edit" banner, but its actual regeneration tooling (`scripts/merge-tr-to-locales.ts`) only ever targets `de/es/fr/it` and is strictly additive (never overwrites, never touches keys it doesn't also have a translation for) — confirmed safe to hand-add new keys to `en.ts`.
- **Existing airport content:** `/travel-info/morocco-airports-guide` already covers "which airport should I fly into" descriptively (Marrakech, Casablanca, Fes, Tangier, Agadir). The new page is linked to, not duplicated — it adds the interactive search/comparison/directory/budget layer that didn't exist before.
- **Existing tour-departure data:** `CITY_HUBS` in `src/data/tour-hierarchy.ts` already has 7 departure cities (Marrakech, Casablanca, Fes, Agadir, Tangier, Ouarzazate, Errachidia) with their own `/tours/from-{city}` pages — reused directly for cross-linking, not duplicated.
- **Contact/consent:** reused `contactInfo` (WhatsApp/email) from `src/data/content.ts` and the existing `Layout`/analytics setup as-is; no new tracking, no new consent surface.
- **Performance:** the new page is its own lazy-loaded chunk — **27.4 KB**, confirmed via the production build — with no new dependency added to `package.json`. Nothing loads globally.

## 3. Data verification (done before any claim was written into the product)

Research was done live (WebSearch/WebFetch), not from memory, and every airport/route claim in `src/data/airports.ts` carries a plain-language note of how it was checked:

- **IATA codes** for all 14 requested airports confirmed against Wikipedia/aviation-reference sources (RAK, CMN, FEZ, AGA, TNG, RBA, OZZ, ERH, ESU, NDR, OUD, TTU, VIL, EUN).
- **Royal Air Maroc's domestic network** (18 destinations, Casablanca-hub structure) confirmed via Morocco World News / Barlamantoday reporting on RAM's October 2025 network expansion, including specific new routes with weekly frequencies (Marrakech↔Laâyoune, Dakhla↔Marrakech, Rabat↔Laâyoune, expanded Casablanca↔Tétouan).
- **Errachidia↔Casablanca was directly checked on Royal Air Maroc's own route-query page** (`royalairmaroc.com/en/flights-from-errachidia-to-casablanca`) — it showed **no bookable results** across every month checked. This is the one route in this feature reported as "no confirmed scheduled service."
- **Ouarzazate↔Casablanca was also directly checked** (`royalairmaroc.com/en/flights-from-ouarzazate-to-casablanca`). Unlike Errachidia, this route showed **real, bookable fares for some specific dates**, with other months showing no results at all. It is reported as **"limited / seasonal"** — date-dependent, not a standing daily schedule, and specifically **not** "no bookable flights." An earlier draft of this feature made that stronger, incorrect claim for this route; a pre-commit review caught the contradiction against the same underlying check, and it was corrected before this release (see §7).
- **Marrakech↔Ouarzazate and Marrakech↔Errachidia** — direct routes *from Marrakech*, distinct from the Casablanca routes above — plus **Marrakech↔Fes, Marrakech↔Tangier**: no verified direct scheduled service found for any of these. Morocco's domestic network is hub-and-spoke through Casablanca, not point-to-point between secondary cities. Presented honestly as "no confirmed service," with a private-transfer suggestion.

None of this is a live feed — it's a dated, sourced snapshot (checked 2026-10-28), and the UI and code comments say so explicitly. These are checked observations at a point in time, not a guarantee that availability stays the same.

## 4. Architecture

```
src/data/airports.ts          verified airport directory + a small, non-exhaustive
                               set of dated domestic-route facts (no live API)
src/lib/flights/links.ts      builds two kinds of external link, both verified
                               working by a live fetch before use:
                               - Google Flights' documented ?q=<natural language>
                                 deep link (any origin/destination/date/pax/cabin)
                               - Royal Air Maroc's real /flights-from-x-to-y pages
src/pages/flights.tsx         the page: hero, search form, results/continue-search
                               panel, airport directory, domestic-route honesty
                               panel, budget planner, tour/contact cross-links, FAQ
scripts/prerender.ts          buildFlightsContent() — the crawler-facing static
                               snapshot, built from the SAME translation keys and
                               the SAME airports.ts data as the live page
```

**No provider adapter class was built for a live fare API**, because there is no live fare API wired up in this release — building an abstraction around nothing would be speculative complexity. The real isolation boundary already exists: every external fact lives in `airports.ts`, and every external link is built by one small, auditable file (`links.ts`). Adding a real provider later (§9) means adding a new function there, not reworking the page.

**No secrets of any kind exist in this feature** — confirmed by a direct grep across every new/changed file. There's nothing to keep secret yet, because there's no paid API.

## 5. What's on the page

- **Search form:** trip type (round-trip/one-way), free-text origin ("anywhere in the world," not restricted to Morocco), destination with a native `<datalist>` autocomplete sourced only from the 14 verified Moroccan airports, native `<input type="date">` depart/return, adult/child steppers, cabin class, and a swap control. Validated inline (`role="alert"`, real error copy) before anything happens.
- **On submit:** no fake "searching…" spinner over fake results. The page builds the two verified external links above and shows them immediately, plus — when both ends resolve to a known Moroccan airport — the matching dated route-status fact from `airports.ts` (Reported scheduled / Limited-or-seasonal / No confirmed flights). A permanent disclosure states the user is leaving the site and that the provider controls final fares, baggage, seats and payment.
- **Airport directory:** all 14 airports, each with name, IATA code, city/region, a one-line verified summary, what part of Morocco it realistically reaches, a "search flights to this city" link, and — for the 7 airports that already have a tour-departure hub — a direct cross-link to `/tours/from-{city}`.
- **Domestic routes panel:** 10 named city pairs, each with an honest status badge: one explicitly-checked "no confirmed service" case (Errachidia↔Casablanca), one "limited / seasonal" case (Casablanca↔Ouarzazate — real fares on some dates, none on others), and several further "no confirmed service" pairs for direct Marrakech routes (Marrakech↔Ouarzazate, Marrakech↔Errachidia, Marrakech↔Fes, Marrakech↔Tangier), which are distinct routes from the Casablanca ones above. Sourced and dated (checked October 28, 2026).
- **Budget planner:** six plain-number inputs (flight budget/traveler, travelers, nights, local transport/day, activities total, accommodation+food/night), an itemized live total, and an explicit "these are your own estimates, not quotes" note. Pure client-side arithmetic — nothing is sent anywhere.
- **Cross-links:** WhatsApp (`contactInfo.whatsapp`), Trip Builder, and Desert Tours — the same contact channel and tour pages the rest of the site already uses.
- **FAQ:** 7 questions answering the exact questions from the brief (which airport, can I fly Marrakech↔Ouarzazate, are prices real, do I need an account, fly-or-drive, etc.), rendered with a real `FAQPage` schema (`buildFaqSchema`) — no `Flight`/`Offer` schema anywhere, since there is no fare to describe.

## 7. Fixes applied after the pre-commit review

A pre-commit review (before any of this was committed) found two concrete, reproducible issues and both were fixed in place. Nothing below is a new live check — each fix was verified against the same evidence already gathered during that review, not a fresh fetch.

**1. Royal Air Maroc deep-link 404, fixed.** The search form's own airport `<datalist>` suggests values like `"Marrakech (RAK)"`. The link builder was slugifying that whole string, producing `.../flights-from-marrakech-rak-to-casablanca-cmn` — confirmed live to return a genuine HTTP 404, since Royal Air Maroc's real pages take a plain city name. Fixed two ways:
   - `resolveAirport()` — previously a private, duplicated function inside `src/pages/flights.tsx` — is now the single, **shared, exported** resolver in `src/data/airports.ts`. The search form resolves the typed origin/destination to a verified airport *before* building the Royal Air Maroc link, and passes that airport's **canonical city name** (e.g. `"Marrakech"`) rather than the raw datalist string.
   - `ramSlug()` in `src/lib/flights/links.ts` additionally **strips a trailing three-letter airport code in parentheses** (`"(RAK)"`, `"(CMN)"`, etc.) before slugifying, as a second, independent layer of defense for any input that reaches it with that suffix still attached.
   - **Regression test added:** `scripts/test-flight-links.ts`, wired into the `test:deterministic` chain in `package.json`. It asserts that `"Marrakech"` and `"Marrakech (RAK)"` build the identical Royal Air Maroc URL, that Marrakech→Casablanca and Casablanca→Ouarzazate build correctly, that the stripped code never appears as its own slug segment, that accented city names (Tétouan, Laâyoune) still normalize correctly, and that a non-IATA parenthetical (`"New York (Newark)"`) is correctly left untouched.

**2. Incorrect Casablanca↔Ouarzazate "no bookable flights" claim, corrected.** The original `src/data/airports.ts` claimed no bookable flights exist on this route. A follow-up check of Royal Air Maroc's own route page for this exact pair found real, priced, bookable fares for some specific dates, alongside other months showing no results — i.e. the original claim was wrong, not merely imprecise. The route's status was changed from `'no-confirmed-service'` to the already-existing `'limited-or-seasonal'` category, and both its domestic-route note and its airport-directory summary for Ouarzazate were reworded to say availability "looks date-dependent, not a standing daily schedule" — without hardcoding any of the specific fares observed as a guaranteed price. Errachidia↔Casablanca was re-examined at the same time and still showed no results, so that claim was left as-is (see §3).

**3. User-facing clarifications added**, so the page's claims match what each link actually does:
   - A new line under the search results — "*This link opens the route only — you may need to re-enter your dates, passengers and cabin class on Royal Air Maroc's site*" — makes clear that only the Google Flights link carries the user's date/passenger/cabin selections; the Royal Air Maroc link is origin/destination only (Royal Air Maroc's own URL format doesn't take those parameters at all).
   - Both flight-network footnotes (the airport directory's and the domestic-routes panel's) now state the checked-on date explicitly — "as of October 28, 2026" — rather than only a vague "recent reporting," and both say plainly that availability can change and must be confirmed directly with the airline.

None of these three fixes introduced a dependency, a secret, a fabricated fare, a live-fare API, or any payment functionality. The budget planner was not touched by this review and remains pure client-side arithmetic over user-entered numbers, explicitly labeled as estimates, not quotes.

## 9. What's not live, and how real pricing could be added later

**Not live today:** flight schedules, fares, seat availability, baggage rules, flight numbers. None of these are fabricated anywhere in this feature.

**What exists instead:** a verified airport/route-fact directory (dated, sourced, non-exhaustive) and two kinds of verified, working external link (Google Flights' natural-language deep link; Royal Air Maroc's own route pages) that hand the traveler off to a real source the moment they need an actual price or booking.

**Options investigated for a future live-data integration** (not integrated now — each needs a real commercial decision by the business before any code is written):
- **Amadeus Self-Service APIs** — has a genuine free tier for schedule/fare-search calls during development, with production tiers priced per call; would need an Amadeus developer account and a signed agreement before production use, and its free tier is explicitly not meant for production booking volume.
- **Travelpayouts** (flight/hotel affiliate aggregator) — free to join, pays commission on completed bookings via its own widgets/API; the brief explicitly rules out requiring a commission arrangement for this release, so this was not pursued, but it's a realistic no-upfront-cost option if the business later decides commission is acceptable.
- **Kiwi.com Tequila API** — historically offered a free-tier booking/search API; access and terms should be re-confirmed directly with Kiwi before any integration, as third-party aggregator terms change.
- **AviationStack / similar schedule-only APIs** — typically provide flight schedules/status, not fares or seat availability — useful for a future "which days does this route operate" feature, not for prices.

**If/when the business picks one:** the integration point is clean — a new function in `src/lib/flights/` (or a small server-side proxy route, if the chosen provider requires a server-side API key, which must never reach the client bundle) that returns real `{price, currency, airline, stops, duration, baggage?, provider, timestamp}` objects; the results panel already has a natural place to render that data without restructuring the page, clearly separating "schedule" from "fare" from "bookable availability" exactly as the brief requires.
